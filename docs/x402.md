# Premium calls and x402

Premium calls are unlocked by paying SUI over the x402 protocol. Soothia's Worker is both the resource server and the facilitator.

## Decision

We implement x402 ourselves, to the v2 specification (`specs/x402-specification-v2.md`, `specs/transports-v2/http.md` and `specs/schemes/exact/scheme_exact_sui.md` in github.com/coinbase/x402).

| Package | Result |
|---|---|
| `@t2000/x402` | Not usable. It was unpublished from npm on 2026-05-27, so it can't be installed or read. |
| `@suimpp/mpp` 0.9.0 | Not usable. It accepts Sui USDC only, with no native SUI path, and depends on `mppx`. Its x402 helpers use the older `X-PAYMENT` headers and an in-process signer. |

Our own version needs only `@mysten/sui`, runs in Workers, and never sees a user's key: the client signs, and the Worker only broadcasts a transaction that is already signed.

## Wire format

Headers carry base64-encoded JSON, as in the v2 HTTP transport.

### 402 response: `PAYMENT-REQUIRED`

```json
{
  "x402Version": 2,
  "error": "PAYMENT-SIGNATURE header is required",
  "resource": { "url": "https://api.soothia.fun/premium/call/p_123", "description": "Premium call by @ada", "mimeType": "application/json" },
  "accepts": [
    {
      "scheme": "exact",
      "network": "sui:mainnet",
      "amount": "20000000",
      "asset": "0x2::sui::SUI",
      "payTo": "0x<caller's address>",
      "maxTimeoutSeconds": 300,
      "extra": { "payPackage": "0x<package>", "payConfig": "0x<config>", "nonce": "<32 hex characters>" }
    }
  ]
}
```

### Retry: `PAYMENT-SIGNATURE`

```json
{
  "x402Version": 2,
  "resource": { "url": "https://api.soothia.fun/premium/call/p_123" },
  "accepted": { "the entry from accepts, unchanged": true },
  "payload": { "signature": "<base64 Sui signature>", "transaction": "<base64 transaction bytes>" }
}
```

The transaction is signed but not executed. The Worker allows exactly `SplitCoins(GasCoin, [amount])` then `<payPackage>::pay::pay(payConfig, nonce, payTo, coin)`.

### Success: `PAYMENT-RESPONSE`

```json
{ "success": true, "transaction": "<digest>", "network": "sui:mainnet", "payer": "0x<address>" }
```

On a failure the status stays 402 and the header carries `{ "success": false, "errorReason": "...", "transaction": "", "network": "sui:mainnet", "payer": "" }`.

## Where we differ from the Sui exact scheme

- The scheme says `payTo` should see a balance change equal to `amount`. Here `amount` is what the payer spends, and `pay` splits it: 90% to `payTo` and 10% to the treasury. The `extra` fields tell a client how to build that call.
- The Worker settles before it reveals the call, because a revealed call can't be taken back.

## Soothia's routes

| Route | Purpose |
|---|---|
| `GET /premium/call/:pickId` | The x402 resource. Free for the caller, after kickoff, or once bought. Otherwise 402, or settles a `PAYMENT-SIGNATURE`. |
| `POST /premium/build` | The unsigned payment for an open quote, because the extension has no connection to Sui. The client checks the bytes before signing. |
| `GET /premium/eligible` | Whether this user may make premium calls. |
| `GET /premium/balance` | An agent wallet's balance. |
| `POST /premium/transfer/build` | An unsigned funding transfer, or a withdrawal of everything. |
| `POST /premium/transfer/execute` | Broadcasts a signed withdrawal. It relays no other kind of transaction. |

A quote lives in KV for five minutes at `x402:<userKey>:<pickId>`. A consumed nonce is marked there, and the contract's own table refuses a second use. A quote can't be spent by another user, because it is looked up by the requester.

## What a premium call does not hide

A premium call hides the side, confidence and stake before kickoff on every Soothia surface. Three things on the chain sit outside that:

- **Pool totals can hint at a side.** If the caller also stakes, the pool's YES and NO totals move.
- **A stake is public on Sui.** The `Staked` event names the staker and the side, so a caller who backs a premium call reveals it there.
- **A buyer can repeat what they bought.** Nothing stops someone who paid from saying the same thing in their own call.
- **The commit hash has no salt.** Its fields are fixed so existing proofs keep verifying. Someone who knows the other fields could try the 99 possible confidence values against the hash.
